# Offline test design

| Test                                                | Behaviour / risk                                                                           | Why this test was added                                                | Oracle                                                                   | Result  |
|-----------------------------------------------------|--------------------------------------------------------------------------------------------|------------------------------------------------------------------------|--------------------------------------------------------------------------|---------|
| `test_offline_from_file_sets_content_type`          | A file request could have a missing or incorrect Content-Type.                             | Check automatic Content-Type selection for `test.txt` in offline mode. | Output contains `Content-Type: text/plain`.                              | Passed. |
| `test_offline_explicit_method_with_data`            | Data could cause an explicit method to be replaced, or the body could be incorrect.        | Check that offline mode keeps `PUT` with JSON data.                    | Output contains `PUT /foo`; parsed JSON equals `{'foo': 'bar'}`.         | Passed. |
| `test_offline_file_preserves_explicit_content_type` | Automatic detection could replace the custom Content-Type, or the file body could be lost. | Check a custom Content-Type together with a file body in offline mode. | Output contains `Content-Type: application/x-custom` and `FILE_CONTENT`. | Passed. |
| `test_offline_does_not_send_request` | Offline mode could accidentally send the request. | Directly check the promise to build and print without sending. | Patched `Session.send` raises if called; `assert_not_called()` passes; output contains `POST /foo` and parsed JSON equals `{'foo': 'bar'}`. | Passed. |
| `test_offline_chunked_file_body` | A file body could be missing when offline and chunked options are combined. | Check offline printing of a chunked file request. | Output contains `POST /foo`, `Transfer-Encoding: chunked`, and `FILE_CONTENT`. | Passed. |
| `test_offline_file_without_extension` | A filename without an extension provides no inferred Content-Type. | Check offline construction from an extensionless file with explicit `--json`. | Output contains `POST /foo` and `Content-Type: application/json`; parsed JSON equals `{'foo': 'bar'}`. | Passed. |
| `test_offline_empty_file_body` | An empty file could be treated as absent input. | Check that an empty file still produces POST with an empty printed body. | Output contains `POST /foo`; the header/body separator exists and `body.strip() == ''`. | Passed. |
